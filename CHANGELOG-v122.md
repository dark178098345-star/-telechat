# tele.chat v122 — аккуратная чистка

Рабочий интерфейс и логика подключённых модулей не изменены. `index.html` оставлен без изменений.

## Удалено

Семь файлов, не подключавшихся к приложению, кэшу или Android-сборке:

| Старые файлы | Работающая замена |
| --- | --- |
| `app-performance-v15.js` | `app-performance-v17.js` |
| `device-presence-v72.js`, `background-presence-v101.js` | `presence-model-v120.js`, `presence-v120.js` |
| `voice-calls-v31.js`, `voice-calls-v31.css` | `voice-calls-v32.js`, `voice-calls-v32.css` |
| `remember-login-v70.js`, `remember-login-v70.css` | `saved-accounts-v75.js`, `saved-accounts-v75.css` |

Из списка предварительного кэширования убраны три устаревшие копии: `app-performance-v17.js?v=105`, `message-context-v36.js?v=105`, `chat-open-loader-v44.js?v=51`. Их актуальные версии `?v=113` сохранены. Кэш обновлён, чтобы лишние копии не оставались на устройстве.

Удалены три теста заменённых реализаций (старые фоновые статусы и одиночное запоминание входа). Проверки текущих статусов, оформления луны, сохранённых аккаунтов и переноса старого входа сохранены. Составной тест надёжности переведён на текущий модуль статусов.

## Намеренно оставлено

- Стили `device-presence-v72.css` и `background-presence-v101.css`: их использует новая система статусов.
- Старые ключи сохранённых аккаунтов и статусов: они нужны для совместимости с данными и другими версиями приложения.
- SQL-миграции, журналы обновлений, старый самостоятельный HTML и ZIP-архив: это не подключаемые модули; их удаление требует отдельной проверки назначения.
- Незавершённые локальные файлы пользователя.

## Проверка и восстановление

Добавлены проверки отсутствия обращений к удалённым модулям, полноты кэша, отсутствия разных версий одного файла и работы файлов без сети после смены кэша. Отдельно проверяются актуальные статусы, сохранённые аккаунты, сообщения, мобильная адаптация, музыка и фотофоны.

Исходные удалённые файлы можно восстановить из предыдущего коммита `2bd8aa4`. Чистка неподключённых файлов упрощает проект, но сама по себе не означает заметного снижения нагрузки на процессор.
