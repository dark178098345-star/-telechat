# tele.chat v123 — загрузка аватарок

## Подтверждённые причины задержки

- Быстрый снимок списка чатов сохранял имена, но удалял фотографию из упакованного поля `status`. После перезапуска аватарки снова зависели от загрузки с сервера.
- Пакетная загрузка списка и `getUser()` имели независимые отметки свежести: открытие чата после получения списка могло повторно загружать того же пользователя вместе с фото.
- На холодном старте запрос аватарок начинался только после получения текстов последних сообщений.
- Мобильный оптимизатор назначал `loading=lazy` всем картинкам, включая аватарки.

## Изменения

- Общий кэш лёгких профилей для списка чатов и `getUser()`: одинаковые запросы объединяются, свежие результаты используются повторно.
- Фото сохраняются в IndexedDB отдельно для каждого вошедшего аккаунта. Снимок списка больше не перезаписывает более полные данные в памяти.
- Устаревший кэш показывается сразу, затем обновляется; новые фотографии обновляются в списке и шапке чата.
- Кэш ограничен 200 записями / 6 МиБ учтённого объёма на аккаунт, срок хранения — 7 дней. Пароли, полные биографии и баннеры в него не записываются. Блокировка хранилища не мешает обычной загрузке по сети.
- Пакеты до 40 пользователей, не более двух одновременно; ограничение запроса 8 секунд, пауза повторов после ошибки. Ответы предыдущего аккаунта и ответы, устаревшие относительно новой версии профиля, не применяются.
- Аватарки запрашиваются параллельно с текстами последних сообщений; на телефоне для аватарок используется eager, для обычных изображений остаётся lazy.
- Оформление, эффекты, состав функций и данные Supabase не изменены.

## Измерения и проверки

В контролируемом браузерном сценарии с задержками запросов 80/120 мс:

- первый список: 316 → 218 мс;
- запросы данных пользователя при списке + открытии чата: 2 → 1;
- повторный запуск со снимком списка и фото-кэшем: 5 мс, 0 запросов пользователей.

Это результаты тестового сценария, не гарантия такой скорости на реальном телефоне. На настоящем сервере отдельно выполнено только чтение 30 лёгких профилей: 128 340 байт ответа, около 1,18 секунды в одном замере. Измерение не использовалось для обещания ускорения на всех сетях.

Добавлены браузерные проверки совместного кэша, повторного запуска, обновления устаревших фото, переключения аккаунта, ограничения размера, ошибок сети и недоступного хранилища. Проверена совместимость с текущими профилями, сообщениями, музыкой, фонами, мобильной адаптацией и кэшем приложения.

Первый запуск после обновления ещё должен получить фотографии. Ускорение повторных запусков появляется после сохранения кэша. Новый APK и миграция базы не нужны.
